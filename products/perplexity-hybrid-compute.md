# Perplexity Hybrid Compute

**创新评分：★★★☆☆**  
**模式：Invisible Compute Routing**

## 真实问题
本地模型更私密、低延迟，云模型更强；让普通用户每次自己决定“这次该本地还是云端、该用哪个模型”会把底层基础设施复杂度暴露到产品表面。

## 旧工作流
用户先选择模型/执行位置 → 再发起任务 → 失败后手动换模型或环境。

## 新工作流
系统根据任务复杂度、隐私、延迟、资源和能力自动决定执行位置与模型，用户只表达目标。

## 核心机制
不是增加一个 model picker，而是把 compute routing 从用户决策变成系统内部策略。

## 为什么不是普通“加 AI”
它并没有依赖一种新模型能力，而是在重新设计产品责任：用户不应该管理底层算力拓扑。

## Composable Test
路由器本身很容易用规则 + benchmark + model gateway 搭建，所以创新度不是最高；价值主要来自把路由真正做到无感、稳定、可解释。

## Human / AI / Software 分工
- Human：表达目标与隐私偏好
- AI/Policy：估计任务类型与能力需求
- Software：选择模型、位置、fallback 与成本策略

## 可迁移原则
> 基础设施选择应该尽量消失在产品内部，而不是成为用户工作的一部分。

## 对本地 Agent / B/G 的启发
本地 Agent 很适合采用：敏感数据优先本地处理；复杂推理或无法完成的任务再升级到云端。用户只看到任务结果，不需要理解每个模型的边界。

## 不确定性
自动路由只有在有持续 Eval、成本和隐私策略时才可靠，否则只是隐藏了一个不可控选择器。

## 跟踪判断
**中度值得跟踪。** 更像基础架构设计原则，而不是强应用层创新。
