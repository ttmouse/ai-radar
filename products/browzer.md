# Browzer

**创新评分：★★★★☆**  
**模式：Source → Self-maintaining Artifact**

## 真实问题
产品代码、数据模型或业务规则变化后，文档、Demo、Changelog、帮助页等派生产物很快过期，维护成本高且容易产生多个“真相版本”。

## 旧工作流
Source 改动 → 人记得去更新文档/演示/说明 → 经常遗漏 → 信息逐渐失真。

## 新工作流
Source of Truth 发生变化 → AI识别受影响的派生产物 → 自动提出或生成同步修改 → 人审核关键变化 → 多个输出持续保持一致。

## 核心机制
AI 不再只是“生成一篇文档”，而是维护 source 与 derived artifacts 之间的长期依赖关系。

## 为什么不是普通加 AI
一次性生成文档很容易；持续知道“源变了以后哪些东西应该一起变”才是机制创新。

## Composable Test
Git hooks + Agent + dependency graph 可以复刻一部分，但真正产品价值在持久映射、影响分析、差异审核与长期一致性。

## 可迁移原则
> AI 生成的内容不应该成为新的孤岛；它最好是 Source of Truth 的可重建视图。

## 对本地 Agent / B/G 的启发
应急系统中的制度说明、检查口径、操作指南、报表定义可由统一业务规则派生。规则一变，AI自动定位需要更新的文档和界面说明，避免多套口径长期漂移。

## 跟踪判断
**值得继续跟踪。**
