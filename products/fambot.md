# Fambot

**创新评分：★★★★☆**  
**模式：Persistent State → Proactive Action**

## 真实问题
个人事务信息分散在邮箱、日历、聊天与提醒中。传统助手只能等人提问，但很多时候真正的问题是：用户并不知道此刻应该问什么。

## 旧工作流
用户自己记住事情 → 打开应用 → 主动询问 AI → AI基于当前输入回答。上下文是临时的，持续跟进责任仍然在人。

## 新工作流
系统持续读取允许访问的信息源 → 维护长期事务状态 → 识别即将发生的义务、变化和异常 → 在合适时间主动提醒或执行低风险动作。

## 核心机制
关键不是更聪明的聊天机器人，而是**持续状态**。AI 从 request-response 工具变成长期存在的后台参与者。Prompt 不再是唯一触发器，状态变化本身可以触发行动。

## 为什么不是普通“加 AI”
如果只是聊天 + Calendar API，很容易拼装。真正的新体验来自持续 Context、事件驱动和主动性：用户不需要知道何时应该调用 AI。

## Composable Test
底层组件可以组合，但真正难的是 state model、trigger policy、通知抑制和信任边界。简单 cron + LLM 很难自然形成好的主动体验。

## Human / AI / Software 分工
- Human：定义偏好与最终高责任决定
- AI：判断哪些变化值得关注、如何解释
- Software：持续同步、状态维护、定时与事件触发

## 可迁移原则
> AI 的下一步不一定是回答得更好，而是知道什么时候应该出现。

## 对本地 Agent / B/G 的启发
本地 Agent 不应该只在聊天窗口等待命令。对于项目、企业风险、整改期限等，应维护 Persistent State，让事件变化触发 AI 分析；只有真正需要判断的结果进入人的队列。

## 不确定性
主动系统最大的失败往往不是答错一次，而是噪音、过度打扰和越权。是否能建立好的 relevance policy 决定长期价值。

## 跟踪判断
**值得继续跟踪。** 重点看主动触发的频率、证据与权限机制。
