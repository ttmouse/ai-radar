# Fireflies Voice Agents

**创新评分：★★★★☆**  
**模式：Recorder → Participant → Worker**

## 真实问题
会议 AI 长期停留在“记录、转写、总结”，但会议本身仍需要人来推进议程、追问、确认行动项，会议后的执行也再次回到人手里。

## 旧工作流
AI 旁听会议 → 生成 transcript / summary → 人阅读 → 人自行跟进任务。

## 新工作流
语音 Agent 不再只是旁听者，而开始在会议或通话中参与：提问、收集信息、确认状态，甚至承担部分标准化沟通任务；会后结果继续进入业务工作流。

## 核心机制
产品身份从 recorder 变成 participant，再进一步变成 worker。真正改变的是 AI 在过程中的位置，而不是总结质量。

## 为什么不是普通“加 AI”
“转写 + 总结”早已商品化。只有当 AI 能实时参与并承担责任时，工作流才被重构。

## Composable Test
语音识别、TTS、LLM、Calendar/CRM API 都可以拼装，但难点在实时 turn-taking、任务边界、转人工、证据记录和失败恢复。

## Human / AI / Software 分工
- Human：复杂判断、关系与例外
- AI：结构化沟通、追问、信息采集
- Software：录音、转写、事件同步、记录

## 可迁移原则
> AI 的价值不一定在会后总结，而可能在进入工作过程本身。

## 对本地 Agent / B/G 的启发
应急场景里的视频核查、电话回访、整改确认，都可以从“AI看材料”升级为“AI参与核验过程”，主动追问缺失信息，再把疑点交给专家。

## 不确定性
实时语音交互对延迟、误解和责任边界要求很高；在高责任场景必须限制其自主决策范围。

## 跟踪判断
**值得跟踪。** 重点看从 meeting intelligence 到真正 voice worker 的转变是否成立。
