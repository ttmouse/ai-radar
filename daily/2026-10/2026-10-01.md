# AI 应用创新日报｜2026-10-01

## 今日结论

**今天没有发现达到核心创新标准的新产品。**

按 Methodology v2 执行 Mechanism Delta、Composable Test v2、Default Workflow Test、Responsibility Shift Test 和 Evidence Maturity 后，今天最值得继续观察的是 **Metaview / fillmore**，但它更像多个既有模式在招聘领域形成了更完整的默认工作流，而不是一个足够独立的新产品机制。

## 重点观察：Metaview / fillmore

- Tracking Score：4/5
- Mechanism Novelty：2/4（已有模式的重要扩展）
- Evidence Maturity：B
- Status：Observe，不进入 Core

### 1. 真实问题

招聘团队过去即使已经使用多个 AI 工具，仍然要人工承担“管理工作本身”：把 intake、候选人搜索、筛选、外联、跟进、面试、评分和 ATS 更新串起来。更深的问题不是某一步效率低，而是上下文和判断信号分散在多个工具中，招聘人员仍然是整个流程的人工 orchestrator。

### 2. 旧工作流

Human 定义职位 → 人工/多个工具搜索 → 人审核候选人 → AI 辅助写 outreach → 人触发跟进 → 人协调 screening / scheduling → 人把结果同步回 ATS → 下一轮继续重新拼上下文。

### 3. 新工作流

Human 通过职位描述或 intake call 给出目标与标准 → 系统形成并持续更新 Ideal Candidate Profile（ICP）→ agents 在后台 sourcing / review / outreach / follow-up / screening → 每一次招聘反馈、拒绝和录用继续修正 ICP → 人主要处理 shortlist、关系和最终判断 → 结果同步回 ATS。

### 4. Mechanism Delta

```text
Recruiter owns workflow orchestration + criteria in their head
→ shared, evolving hiring criteria becomes machine-readable operational context
→ Agents own persistent execution; humans own judgment and exceptions
```

真正有意思的不是“AI 自动找候选人”，而是 **招聘标准从人的隐性判断，逐渐变成一个持续学习、可被多个 Agent 共同消费的 operational object（ICP）**。

### 5. Composable Test v2

用现有 LLM + sourcing API + email automation + calendar + ATS API + workflow engine，1–2 天可以拼出 sourcing → outreach → follow-up → booking 的大部分 Happy Path，因此单看 fillmore 的自动化链路并不构成强创新。

但稳定产品体验还依赖：共享 role context、跨步骤状态、反馈回流、可解释 candidate rationale、权限/guardrail、ATS 同步和长期 criteria calibration。这使它属于 **Composable but Structural**，而不是纯 Commodity。

仍然不进入 Core 的原因：这些结构目前可以被已有 Pattern #03 Goal → Autonomous Work、#04 Organization Context Layer、#17 Judgment Queue、#19 Organization Learning Loop、#25 Business Semantic Layer 共同解释。

### 6. Responsibility Shift

| 角色 | Before | After |
|---|---|---|
| Human | 定标准、找人、推进、跟进、同步、判断 | 定目标/标准、校准、处理关系与关键判断 |
| AI | 单点生成/总结 | 持续 sourcing、review、outreach、follow-up、screening，并根据反馈调整 |
| Deterministic Software | ATS/CRM 保存流程状态 | 继续承担记录、同步、权限、审计和确定性动作边界 |

关键变化：**Human 从 workflow operator 向 criteria owner + judgment handler 移动。**

### 7. 事实 / 推断 / 未知

**已确认事实**
- Metaview 官方称 fillmore 可自主寻找候选人、个性化 outreach、管理 follow-up、预订 screening calls。
- 官方称多个 agent 共享 context；role 的 ICP 会基于招聘决策、application review、interview results 等持续改善。
- ICP 可被人查看、编辑、override；candidate recommendation 有 rationale。
- 官方称系统有 company knowledge/rules、non-compliance alerts 和 audit trail。

**合理推断**
- ICP 已经接近“招聘意图/标准的可执行语义对象”，而不只是 prompt。
- 招聘团队的主要操作界面可能逐渐从 task list 转向 judgment/exception queue。

**未知**
- ICP 的内部数据模型、版本化和多角色冲突如何处理。
- feedback 到 ICP 的更新是规则、LLM synthesis 还是统计学习。
- Agent 的具体 approval threshold、失败恢复和 eval 机制。
- 实际客户是否真的把这一模式作为默认端到端工作方式，而非只启用部分 agent。

### 8. 可迁移产品原理

最值得迁移的不是“垂直 Agent”，而是：

> **把人的隐性判断标准变成一个持续校准、可解释、可编辑、可被多个 Agent 共享的 Operational Criteria Object。**

但这暂不新增 Pattern。它与 #25 Business Semantic Layer、#19 Organization Learning Loop 高度相邻，需要更多独立产品证据证明“Criteria as First-class Operational Object”值得独立存在。

### 9. 对 AI 产品 / 本地 Agent / B/G 的启发

对本地 Agent：不要只持久化 conversation memory。更值得持久化的是“当前工作的判断标准”，并允许每次人工接受/拒绝结果后更新标准。

对应急/B/G：例如专家判断企业风险时，不应该只保存一次检查结果；可以逐渐形成每个任务/对象的可解释检查 criteria，并由人工修正持续校准。Agent 执行检查，专家主要处理边界案例和标准修正。

### 10. 可直接复刻 / 不值得抄

可复刻：
- Role/Task Criteria 对象
- 人工 accept/reject → criteria feedback loop
- Agent shared context
- rationale + override
- exception/judgment queue

不值得抄：
- 为每个招聘步骤机械拆一个 Agent
- 把 multi-agent 数量当卖点
- 单纯自动发邮件/跟进/预约

### 11. 最大反证

Metaview 的公开叙事非常接近“Recruiting's Claude Code moment”，但目前最强证据仍来自官方。若真实客户只是把它当 sourcing/notetaking/application-review 工具集合，那么所谓 end-to-end agentic recruiting 仍可能是平台包装，而非真实默认工作流。

另一个反证是：ICP 持续学习本身可被视为 #19 Organization Learning Loop + #25 Business Semantic Layer 的垂直实现，并没有创造新模式。

### 12. 跟踪判断

**Observe，4/5。**

继续跟踪的关键不是它增加多少 recruiting agents，而是：**ICP 是否真正成为招聘工作的 Source of Truth，并逐步取代 recruiter 脑内的隐性标准。** 如果这一点得到独立客户证据，它才可能从“已有模式组合”升级为新的机制候选。

## 其他候选

### Restate — Reject as application-layer innovation / Track as infrastructure

9 月 30 日融资新闻再次强化 durable execution for agents。Restate 能让 agent execution 成为可暂停、恢复、重试、寻址的持久过程，并解决 human approval、side effect、failure recovery 等生产问题。这对 Agent Runtime 很重要，但属于基础设施成熟，不是新的应用层产品机制。它更像支撑 #06 Persistent State、#14 Governance、#28 State Transition 的底层能力。

### Tote HQ Genie — Reject

自然语言查询便利店实时运营数据并自动化 recurring tasks。当前证据显示主要是 NL analytics + automation，1–2 天可用 semantic/data layer + LLM + workflow automation 复刻核心体验；没有看到新的对象模型、责任结构或交互原语。

### World ID agent delegation / Human-in-the-loop — Observe as infrastructure pattern evidence

World ID 为 agent delegation 和高风险动作提供可验证的人类授权证明，机制有价值，但主要属于 identity/authority infrastructure，并强化已有 #15 Proposed Action 和 #22 Agent Identity；不新增 Pattern。

## 与历史 Pattern 的比较

今天没有新增 Pattern。

最值得保留的机制候选是：

**Criteria as First-class Operational Object**

但暂时只作为 Observation / Candidate seed，不编号。它需要证明：
1. criteria 不只是 prompt/config；
2. 它有持久状态和明确 schema；
3. 人工 judgment 会持续修改它；
4. 多个 agents 以它作为共同执行依据；
5. 至少在三个独立产品中出现。

否则应继续归入 #19 + #25。

## Methodology Reflection

今天验证了 Methodology v2 的一个价值：旧 Composable Test 很可能直接淘汰 Metaview，因为 sourcing/outreach automation 很容易拼装；v2 能进一步识别“技术可拼，但 Criteria Object + Responsibility Shift 仍可能有结构变化”。

同时也说明 Pattern Candidate 机制是必要的：如果按旧规则，很容易因为“持续学习的 ICP”直接创建 #31；现在证据不足，应该先积累。

> **Agent 真正接管一类知识工作，不只是要接管“执行步骤”，还需要把专家脑中的判断标准外化成一个可持续校准、可解释、可被多个 Agent 共同执行的对象。**
