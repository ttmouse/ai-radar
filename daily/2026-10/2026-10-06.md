# AI 应用创新日报｜2026-10-06

## 今日结论

**Core：1 — OpenAI dots。**

它不是今天发布的新产品（2026-09-29 发布），而是本次 **7–14d Maturation Window** 中证据成熟后进入 Core：OpenAI Help Center 在发布后继续补全 Custom Rules、Auto-review、proactive research restrictions、pause/reset lifecycle 等关键机制，使它从“always-on agent 的营销描述”变成可以分析产品结构的对象。

评分：**Tracking 5/5 · Mechanism Novelty 3/4 · Evidence B · Composable but Structural**。

## 1. 它解决什么真实问题

传统 AI 助手即使可以长时间执行，本质执行单位通常仍是 conversation / task。用户仍然负责记住“什么需要持续发生”、重新发起、补 context、判断下一步。

dots 试图把产品关系从“把任务交给 AI”推到“把一段持续责任交给一个长期存在的 AI actor”。官方明确将 dots 描述为 always-on agents，可以承担 ongoing responsibilities、跨 conversations 继续工作，在用户定义的权限边界内主动推进。

## 2. 旧工作流

```text
Human owns responsibility
→ notices need
→ opens AI
→ gives task
→ agent executes
→ returns result
→ task/session ends
→ Human remembers next action
```

## 3. 新工作流

```text
Human defines goal + boundaries
→ persistent dot owns ongoing responsibility
→ maintains memory / tasks / connected-app context
→ proactively continues between conversations
→ deterministic permission/safety layers gate actions
→ Human handles consequential approval / exception / judgment
→ feedback changes future behavior
```

## 4. 最关键的产品机制

### Task Delegation → Responsibility Delegation

“后台 Agent”不是新机制。真正值得关注的是：**责任开始跨 task/session 持久存在，并绑定到一个拥有 identity、memory、rules、tasks、activity 与 lifecycle 的 Agent。**

从产品结构推断，未来更合理的一等对象不是 Agent 本身，而是：

```text
Responsibility
├── principal / owner
├── persistent agent
├── goal
├── context / memory
├── connected tools
├── ongoing tasks
├── authority / rules
├── approval policy
├── activity / evidence
└── lifecycle
```

OpenAI 没有公开说明内部存在名为 Responsibility 的统一 schema，因此“Responsibility object”属于分析判断，不是已确认实现。

## 5. Composable Test

1–2 天可以用 Agent Runtime + scheduler + memory + MCP/plugins + cloud browser + approval UI 拼出大部分 Happy Path。

因此 **always-on agent 本身不构成创新**。

仍然通过压力测试的原因是：真正产品结构是把 identity + memory + proactive work + permissions + approval + lifecycle 收敛成一种长期委托关系。如果复制品仍要求人不断重新 prompt、重新解释 context、重新维持目标，它复制的是 execution capability，不是产品机制。

结论：**Composable but Structural**。

## 6. Human / AI / Deterministic Software 分工

| Actor | Before | dots |
|---|---|---|
| Human | 维持责任、发起任务、记住下一步 | Goal / Responsibility Owner + Boundary Setter + Exception Judge |
| AI | 回答/一次性执行 | 长期维护 context、主动决定 next step、跨会话推进 |
| Deterministic Software | session/tool permission | plugin access、Custom Rules、approval state、Auto-review、core safety、pause/reset lifecycle |

最重要的 Responsibility Shift：**Human 从 Task Initiator 变成 Responsibility Owner。**

## 7. 架构 / Runtime / Context / Approval：事实与推断

### 已确认事实

- dots 基于 GPT-6 Astra；有自己的 cloud computer。
- 可连接 OpenAI plugin ecosystem 中 4,000+ apps。
- 可通过 ChatGPT、短信、Slack、Teams 等渠道交互。
- 可跨 conversations 持续工作并保持 context。
- Custom Rules 可以定义支持动作是独立执行、预授权、执行前询问还是交还用户。
- core safety requirements 不能被 Custom Rules 或普通用户批准关闭。
- Auto-review 会在部分动作执行前检查 instructions、Custom Rules 和 safety requirements。
- proactive research 有独立工具限制，不能直接给其他人发消息、通过 plugins 修改内容或控制 browser/computer。
- pause/resume 与 reset 是 dot lifecycle；reset 会删除 conversations、saved memories 和 scheduled tasks。

### 合理推断

- dot 需要持久 state store 把 identity / memory / tasks / permissions / activity 绑定到同一个 actor。
- proactive execution 与 interactive conversation 很可能存在不同 policy path。
- Auto-review 很可能是与主执行 loop 分离的 policy/eval path。

### 未知

- memory schema 与写入/遗忘策略。
- proactive trigger / scheduler 的具体机制。
- Auto-review 的实现、误报率和 eval。
- 长周期失败后的 recovery / accountability。
- 未来多个 dots 如何共享或隔离 context、authority、responsibility。

## 8. 可迁移产品原理

1. **持久的应该是 Responsibility，不只是 Agent。** Agent identity 回答谁在工作；Responsibility 回答它长期负责什么。
2. **Proactivity 必须和 Authority 一起设计。** 越主动，越不能只靠 prompt 约束。
3. **Human-in-the-loop 从每一步确认迁移到 boundary / exception / consequential action。**
4. **Pause / Resume / Reset / Revoke 是长期 Agent 的基础交互原语。**

## 9. 对 AI 产品、本地 Agent、应急/B/G 的启发

对于本地 Agent，不应该继续只加 Tool；应该增加 Responsibility Registry：

```text
Responsibility
→ Goal
→ Persistent Context
→ Trigger / proactive loop
→ Proposed Action
→ Policy Gate
→ Execute
→ Activity / Evidence
→ Feedback
→ Continue / Pause / Complete
```

对于应急管理，专家 Agent 可以长期承担“持续负责某批责任主体风险变化”的责任：scope 指定企业/区域/风险类型；authority 区分可查看、可分析、可生成建议、不可签发正式文书；trigger 来自新证据、风险变化、周期节点；高风险/证据冲突进入人工 exception。

这比“周期任务 + 自动化”再往前一步：**任务会结束，责任可以跨任务持续存在。**

## 10. 什么可复刻 / 什么不值得抄

### 可直接复刻

- Responsibility registry
- persistent agent identity
- explicit scope / policy
- activity timeline
- pause / resume / revoke
- action-time policy gate
- exception queue

### 不值得抄

- avatar / pet 等人格包装，除非有证据证明改善长期责任关系。
- 4,000+ integrations 的数量竞赛。
- 为了体现主动性而产生大量通知。

## 11. 最大未知与反证

最大的反证不是技术，而是**用户行为**：如果用户最终仍把 dot 当更强的 ChatGPT / 通用 Agent，而不真正长期委托责任，则 Responsibility Delegation 只是营销叙事。

另外，多数底层能力高度可组合；当前只有一个 dot，多 Agent responsibility allocation 尚未验证；长期主动 Agent 还可能产生错误累积、目标漂移、权限疲劳和 notification burden。

## 12. 是否值得继续跟踪

**5/5，继续跟踪。**

重点看：是否出现 Responsibility/role/ownership 管理界面；多 dots 是否支持责任拆分/转移/冲突解决；Activity View 是否从流水日志升级为 outcome/exception 视图；Custom Rules 是否最终成为稳定 policy object。

## 与历史 Pattern 比较：真正新增什么

最接近 #03 Goal → Autonomous Work、#06 Persistent State → Proactive Action、#14 Governance Layer、#17 Judgment Queue、#22 Agent Identity、#27 Context Belongs to Work。

今天不新增正式 Pattern。

形成 Candidate：**Responsibility Delegation / Responsibility as Persistent Agent Contract**。

它真正新增的命题是：

> Agent-native 软件的长期单位可能不是 Task，也不是 Agent，而是“人把一段持续 Responsibility 在明确 Authority Boundary 下委托给一个持久 Actor”。

需要至少另外两个独立产品验证后再考虑 Pattern 编号。

## 今日主动淘汰 / 观察

- **Microsoft Copilot Autopilot — Observe。** 官方描述它为持续运行、主动执行的个人化 Agent，即使用户离线也能推进工作；并提出从 question → task → role/responsibility 的演进。这是 Responsibility Delegation Candidate 的第二个强信号，但 Autopilot 仍在 Private Preview / rollout 阶段，公开机制细节少于 dots，不单独进入 Core。
- **Jedify Data Agents — Reject/Observe 边缘。** monitor metrics → investigate changes → recurring analysis 很实用，但主要是 persistent monitoring + agent workflow，现有 #06/#25/#26 足以解释。
- **Formas.AI Cartesian — Observe。** AI agent + 3D kernel/toolkit 让自然语言进入可编辑 CAD/3D 操作，值得观察 Artifact/Object 编辑机制，但当前证据更像 domain tool-use 进步。
- **Zimyo 3.0 / HR agents — Reject。** 多步 HR workflow + HITL，未看到新的对象模型或责任结构。

## Methodology Reflection

### 双时间窗第一次证明有价值

如果只看 24–72h Fresh Window，今天很可能得出 Core=0；但 dots 在 9/29 发布后，Help Center 和安全机制文档继续补全，到了 10/05–10/06 才足以判断 Custom Rules、Auto-review、proactive restrictions、lifecycle。

因此正式确认：**发布日期 ≠ 研究成熟日期。** Maturation Window 不只是补漏，而是独立 discovery channel。

### 新增一个去重原则

当两个产品同时出现同一 Candidate（今天 dots + Microsoft Autopilot 都指向 Responsibility Delegation）时，不因为第二个产品也很强就重复写 Core。优先选择证据最完整者做深拆，另一个作为 cross-product evidence。这样 Pattern 库更快积累独立证据，同时避免日报被同构产品占满。

## 今日结算

- Core：**1（OpenAI dots）**
- Observe：Microsoft Copilot Autopilot、Formas.AI Cartesian
- Reject / 边缘：Jedify Data Agents、Zimyo 3.0
- 新正式 Pattern：**0**
- 新 Pattern Candidate：**Responsibility Delegation**

### 今日最值得记住的产品创新养料

> **Agent 时代真正值得产品化的，不只是“让 Agent 持久存在”，而是把人的持续责任变成一个可委托、可设边界、可暂停、可撤销、可审计的长期关系。Task 会结束，Responsibility 不一定结束。**
