## 1. Core（条件入选）：UseIt Studio

- 官网：https://useit.im/
- Product Hunt（2026-10-21）：https://www.producthunt.com/products/useit-studio-from-idea-to-delivery
- 状态：Core（条件入选）；Tracking **4/5**；Mechanism Novelty **3/4（产品结构变化，不是新通用 Pattern）**；Evidence **B**。
- 发布 ≠ 成熟：10 月 21 日上线；10 月 22—24 日官网具体生产示例及创始人说明使「设计对象 + 生产约束」比发布口号更清晰。

### 真实问题与旧工作流

用户想制作贴纸、亚克力立牌或包装盒。通用图像模型能给视觉稿，却不能保证尺寸、出血、刀线、压痕、白墨层等制造约束。传统路径是：文字需求 → 图片/设计草图 → 设计师在 Illustrator 重新建可编辑文件 → 制作刀版/印刷层 → 人工印前检查 → 打样与工厂沟通。瓶颈不是图片生成速度，而是**视觉意图与可制造业务对象之间缺少连续性**。

### 新工作流（官方演示描述）

需求/草图 → AI 追问制作要求 → 创建可编辑分层设计（文本/图形/矢量） → 用户圈选局部、自然语言修改 → 2D/3D 联动预览 → 按产品类别生成 CUT/CREASE/BLEED/ARTWORK 等结构与白墨层 → 根据制造知识库/模板校验 → 输出可在 Illustrator 中继续编辑的 .ai 与打印 PDF → 真实生产方仍需最终打样验证。

官网展示 200×170×60mm 礼盒、80×100mm 亚克力立牌、3mm bleed 与分层文件示例。创始人在 Product Hunt 明确表示制造知识库来源于工厂模板和规格表，覆盖尺寸、出血、安全区、材料、印刷方式与工艺，并称会对最终文件做规则复核。**这是厂商可核对的陈述，不是独立证明每个输出都能生产。**

### Mechanism Delta：从图像生成到「可执行生产对象」

**Before：Prompt → Image → 人工重建生产文件。**

**After：Intent → Editable Design Object + Manufacturing Constraints → 局部编辑/校验 → Manufacturing Artifact。**

AI 的变化不只是「自动设计」，而是把过去必须由专业人员翻译的设计意图，直接落到有图层、尺寸、刀线、生产约束的**持久对象**上。用户修改的是同一个可编辑对象，不必每次重新生成一张图。真正的价值假设是减少「视觉稿 → 印前文件」这次跨专业交接。

### Human / AI / Deterministic Software

| 角色 | 新分工 |
|---|---|
| Human | 定义用途、材料偏好、视觉目标；圈选局部并决定是否接受；生产前最终审核 |
| AI | 澄清模糊意图、构建设计元素、提出布局、理解局部修改 |
| Deterministic Software | 保留图层/尺寸/刀线关系，应用出血等可计算规则，生成可编辑文件与生产输出；应承担规则校验 |
| 外部生产方 | 验证真实材料、设备、色彩、加工公差与最终打样，不能被网页上的「production ready」替代 |

### Composable Test 与 Default Workflow

**容易在 1–2 天拼出的部分**：图像生成 + SVG/Illustrator 脚本 + 固定模板 + 对话修改 + 简单 PDF 导出。仅有这些不算强创新。

**难以在 1–2 天复制的产品机制**：同一个结构化对象跨局部编辑、真实刀版、材料规则、2D/3D 预览、Illustrator 可编辑输出而持续保持一致；尤其是跨多类制品的制造规则与回归校验。这里属于 **Composable but Structural**，且部分能力接近 Non-trivial System；难度本身不构成创新，**减少跨专业对象重建**才是结构性增量。

Default Workflow Test：如果用户确实能以「可制造设计对象」为唯一主对象完成多轮修改与交付，就可能替代旧流程；但目前缺少真实工厂交付和长期复用的独立证据，因此只是**条件入选**。

### 架构：事实 / 推断 / 未知

- **已确认（厂商资料）**：可编辑图层、局部对话修改、2D/3D 预览、出血/刀线/白墨层、Illustrator 编辑与生产文件；创始人称 Agent 在设计软件中工作并使用工厂模板/知识库做校验。
- **合理推断**：存在结构化场景/图层模型、模板规则引擎、生成与编辑工具链；可能有可持久化的设计状态与编辑历史。没有证据证明具体 Agent Runtime、Memory 数据结构、Tool 协议或 Eval 实现。
- **未知**：局部编辑是否可靠保持其他图层与生产约束；色彩管理/材料/刀版精度；生产文件通过真实工厂验收的比例；失败时如何回滚；用户是否减少净投入时间；制造知识库覆盖范围。
- **分析判断**：它是「AI 生成结果直接成为可操作、可校验的真实业务对象」的有价值纵向案例；不是通用的新设计模式。

### 历史 Pattern 对比：它真正新增了什么？

- **#10 Artifact → Semantic Object → Action**：不是仅识别一张图，而是让图成为可修改且可生产的对象；属深度扩展。
- **#13 Deterministic / Probabilistic Split**：审美与意图交给 AI，出血/刀线/尺寸与格式交给规则系统；属领域化强化。
- **#28 Generation as State Transition**：同一个设计对象在多轮编辑中演化，而非一次性图片输出；已有结构可解释。
- **#30 Intent as Source of Truth**：只有当制造意图长期约束文件更新且可验证时才接近；目前证据不足。
- **真正新增的 Finding**：**「制造约束与可编辑设计对象必须同时成为主工作流的一部分，否则 AI 只是生成视觉草图」**。这不是新 Pattern，**不新增 #31**。

### 可迁移原理与落地

**AI 产品设计**：不要把「生成结果」默认当最终对象；先定义后续真实系统可接受的业务对象和不变量。用户可以在可视界面表达意图，确定性软件维护对象结构和校验。

**本地 Agent / AI 原生研发**：已有 CLI、文件访问、浏览器、MCP 时，先复刻「AI 生成/修改结构化对象 → 规则校验 → 原生文件导出 → 人审核」；不必抄它的图像生成 UI、制造数据库和 3D 渲染器。

**应急管理 / B/G**：隐患不是「AI 输出的一段描述」，而是有检查点、证据、责任主体、整改状态、审批权限的结构化业务对象。让 AI 生成/修正建议，软件维护状态与规则，专家在关键节点确认。不要把现场安全结论类比成可自动证明的印前尺寸规则：现实证据的真实性仍需独立获取。

**最小验证**：抽取 20 个真实制品/业务对象，比较 AI-only 图片/文案与结构化对象方案在返工次数、规则违规率、人工审核时间、实际交付通过率上的差异。

**最大反证**：如果导出的 Illustrator 文件只是不可维护的伪图层，或生产前仍需设计师大规模重建，那么所谓「对象连续性」就不成立，Core 应降级为 Observe。

## 2. Observe：DotMD（2026-10-23 前后）

- Product Hunt：https://www.producthunt.com/products/dotmd-3
- 官网：https://getdotmd.com/
- Tracking **4/5**；Novelty **2/4**；Evidence **B/C**。

**真实问题**：Coding Agent 写大量 Markdown 需求、计划、说明，人需要引用段落让 Agent 改，改后难核对是否误改。

**工作流**：Agent 通过本地 MCP 把文件交给人 → 人在确切段落做行级评论 → Agent 获取引用片段/行号/评论 → 修改原文件 → 人在原位置看到 diff 并逐条接受或退回。创始人在 Product Hunt 明确说明 MCP 返回评论定位与引用文本，Agent 根据本地文件自行读取必要上下文；本地 MCP 监听 localhost。

**Delta**：Human 从「聊天反馈」切换为「直接在工作对象上标注与裁决」。这是有价值的 Judgment/Shared Artifact 交互，但可以由 Markdown 编辑器 + diff + MCP + 行级评论较快拼出 80%；#15、#17、#21、#27 已能解释，**不晋级 Core**。本地 Agent 值得复刻「评论锚点 → 结构化修订请求 → 原位 diff → 接受」；不必另造 Markdown 编辑器。未知：跨文件改动、锚点漂移、并发编辑、实际长期使用率。

## 3. Maturation：Apate（2026-10-14）

- 官网：https://www.apate.ai/products
- TechCrunch 2026-10-14：https://techcrunch.com/2026/10/14/apate-sends-ai-agents-undercover-to-get-scammed-so-they-can-gather-fraud-intelligence/
- Tracking **4/5**；Novelty **2/4**；Evidence **B**；维持 Observe。

**机制**：AI 用多语言角色主动与诈骗方交互，带着特定情报任务获取账号、钱包、诈骗渠道等，再向银行/电信等客户提供威胁情报。与被动告警不同，它把「证据缺口」变成 Agent 主动调查目标。

**Composable Test**：电话/消息 Agent + persona + 情报抽取 + 任务目标 + 风险控制可以复刻演示；大规模对抗训练、真实诈骗环境的安全性和合法性不易复刻。#23 Adversarial Agents + Independent Referee（对抗结构相关但不完全同构）、#24 Evidence Gap → Active Investigation 更贴近。并无独立新 Pattern。TechCrunch 的规模与成效数字大多来自公司/客户陈述，不能当因果证明。

**迁移**：应急管理可借鉴「AI 主动追问缺失证据」，但绝不能直接借鉴虚构身份、欺骗式取证；监管事实必须有可追溯、合法且可复核的来源。

## 5. 对 Radar 本身的自检

**Methodology**：没有发现需要修改顶层目标或增加规则的缺陷。今天的核心判断依赖 v2 已有的 Mechanism Delta、Composable Test、Default Workflow、Evidence Maturity；**不为更新而更新**。

**证据反例**：Shipped or Stalled 10 月 22 日发布的公开注册表追踪企业 Agent 从 Pilot 到 Production/Scaled/Killed，并附来源；它本身不属于 AI 应用层产品机制创新，但提醒 Radar 区分「宣布了产品」与「已实际部署、持续使用」。官方：https://shippedorstalled.ai/ 。该站截至 10 月 21 日数据页显示 101 个项目，与 10 月 22 日新闻稿引用的 59 个项目属于不同更新时点，不应混为同一口径。部署状态不等于机制创新强度，不能直接作为 Core 评分。

**Pages**：优先修复已知缺陷——Methodology 应为一级知识视图，并从 `methodology/methodology-v2.md` 和 `methodology/changelog.md` 实时读取规则、版本、变化原因。不要新增视觉风格或重构信息架构。README 历史统计需与真实数据对齐。
