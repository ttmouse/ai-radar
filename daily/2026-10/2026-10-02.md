## 为什么今天选它

Decagon 10 月 1 日发布 Voice 3、Personal Agent Gateway、Agent Modules、Duet Apprentice。四个发布中，真正达到应用层机制创新标准的不是新语音模型，也不是更多 Agent Module，而是 **Personal Agent Gateway + PACT**。

它针对一个正在出现的新现实：用户开始让 personal agent 代表自己去订票、购买、取消、谈判和联系客服。传统企业软件默认“请求者 = 账户本人”；Agent 时代这个假设开始失效。

Decagon 的产品结构把三类 Actor 显式分开：

```text
Human / Principal
→ delegates scoped authority
→ Personal Agent
→ agent-native channel / PACT
→ Business Agent
→ enterprise policy + deterministic permission checks
→ Enterprise System
```

核心 Mechanism Delta：

> 企业系统从“识别谁正在操作”，升级到“识别哪个 Agent 正代表哪个 Principal、在什么 Scope 下操作”。

## 1. 真实问题

Personal Agent 可以像人一样拨电话或打开聊天，但企业无法因此知道：

1. 对面是不是 Agent；
2. 它代表哪个客户；
3. 客户允许它查看什么、修改什么；
4. 企业应对 Agent 使用什么不同政策；
5. 两个 Agent 陷入循环或冲突时谁来升级处理。

Decagon 明确指出，阻止 Agent 会推动它们更擅长伪装成人；完全放开又会制造账户安全、权限和策略滥用问题。

## 2. 过去工作流

```text
Human
→ Website / App / Phone / Chat
→ Business UI / IVR
→ Human / support bot
→ Enterprise system
```

登录 Session、账户验证、电话核验把 Principal 与 Actor 隐含地视为同一个人。

## 3. 新工作流

Personal Agent Gateway 增加：

- personal agent detection；
- agent-native dedicated channel；
- Human 与 Agent 可走不同 AOP；
- 企业定义 permission scopes；
- 用户明确授予 Agent scopes；
- PACT 用 delegated authorization 表达代理关系；
- Business Agent 与 Personal Agent 都有各自的 Human escalation。

## 4. 最关键产品机制

不是“Agent 和 Agent 可以聊天”。A2A 已经解决大量通信问题。

真正变化是：

```text
Principal ≠ Acting Agent ≠ Business Counterparty
```

软件第一次必须把“谁拥有权利”和“谁实际执行动作”作为两个不同对象处理。

这会产生新的产品对象：Delegation。

## 5. Composable Test v2

OAuth 2.0 + A2A/MCP + Agent Runtime + policy engine + approval UI，可以很快做出 identity、scope token、Agent-to-Agent 请求、高风险审批和 audit 的 Demo。

所以从技术组件看，它高度 composable。

但组合性没有消除结构变化：传统 SaaS 的基本假设是 Human 是直接 Actor；这里 Principal、Delegate、Enterprise Counterparty 被拆开，并且权限进入业务工作流本身。

因此判断：**Composable but Structural**。

## 6. Human / AI / Deterministic Software 分工

| Actor | 新责任 |
|---|---|
| Human | 定义目标、授予 scope、处理例外 |
| Personal Agent | 代表 Principal 持续提出并推进请求 |
| Business Agent | 代表企业解释请求、执行政策、协商与升级 |
| Deterministic Software | 验证 delegation、scope、policy、audit，守住模型不可自行改变的边界 |

Human-in-the-loop 从“自己完成每个动作”迁移到“定义授权边界 + 处理例外”。

## 7. 事实 / 推断 / 未知

### 已确认

- Gateway 可检测 personal agents，并提供专用 channel。
- Human 与 Agent 可以使用不同 AOP。
- 企业定义 scopes，用户授予 scope；没有 scope 时相关 AOP 部分不会暴露。
- PACT 建立在 Agent2Agent 与 OAuth 2.0 delegated authorization 上。
- 双方都支持 escalation。

### 合理推断

长期 delegation 会需要 expiry、revocation、purpose、金额/次数/时间等 constraints；Agent 请求量大幅增加后，rate limit、经济成本与反滥用也会成为 policy。

### 未知

PACT 是否能成为 Decagon 之外的协议；Agent detection 是否可靠；scope 是否能表达复杂现实委托；双 Agent 长时间协商如何防越权和诱导。

## 8. 与历史 Pattern 比较：新增了什么

它强化 #14 Governance、#15 Proposed Action、#22 Agent Identity、#23 Adversarial Agents、#26 Agent-facing System of Record。

但现有 Pattern 没有完整表达：

> **Agent Identity ≠ Principal Authority。**

因此今天只形成 Candidate：

**Delegated Agency / Principal → Agent → Scoped Authority**

按 Methodology v2 不创建 #31。等待至少两个独立产品/协议重复出现同一结构。

## 9. 可迁移产品原理

1. Identity 与 Authority 必须分离。
2. Agent 不只是新渠道，而是新的 Actor Type。
3. 授权必须进入业务流程语义，而不只是 IAM。
4. Agent-to-Agent 不代表双方目标一致。
5. Human-in-the-loop 会迁移到授权边界和例外判断。

## 10. 对本地 Agent / B/G 的启发

本地 Agent 已经有 Runtime、CLI、Browser、MCP 后，不要只继续堆 Tool。应该增加统一 Delegation Object：

```text
Delegation
├── principal
├── agent_id
├── scope
├── resource
├── constraints
├── purpose
├── issued_at
├── expires_at
├── revocation
└── audit trail
```

在应急/B/G 系统里尤其重要：专家可以授权 Agent 查看和分析某批企业，但“查看资料”“生成建议”“发送督办”“签发文书”必须是不同 scope。Runtime 在 Tool execution 前确定性校验，而不是让 LLM 自己决定权限。

## 11. 最大反证

PACT 可能最终只是 OAuth delegated authorization 的 Agent 场景包装。如果企业没有动力建立 agent-native channel，Personal Agent 长期仍靠 Browser/UI 模拟人类，那么今天的结构判断会被高估。

真正要跟踪的不是协议名字，而是：

> 企业是否开始把代理关系存成长期可查询、可撤销、可审计的业务对象，并围绕它改变服务工作流。

## 12. 跟踪判断

**5/5，重点跟踪。**

Decagon 的重要性不在于“又做了一个 Agent”，而在于它开始承认 Agent 进入真实经济活动后的一个结构事实：**权利主体、代理执行者、服务提供方是三个不同 Actor。**

## 今日其他候选

### Decagon Voice 3 — Observe / 不单独入选

Duplex architecture 让低延迟 conversational model 与更强 reasoning/tool model 并行工作，解决 Agent 执行长任务时语音沉默、打断和 turn-taking 问题。交互体验明显提升，但主要是语音 Runtime / model architecture 的进步，不足以独立形成应用层 Pattern。

### Decagon Duet Apprentice — Observe

它从 onboarding docs、团队频道和资深员工处理的 escalation 中学习，持续起草/更新 AOP。方向很强，但目前主要强化 #19 Organization Learning Loop 与 #12 Self-maintaining Artifact。需要继续观察它是否把“Operational Criteria / SOP”真正做成可持续校准的一等对象。

### Mixpanel Agent Intelligence — Observe / Reject Core

Agent outcome analytics 很重要，但当前更像 Agent Ops/analytics 基础设施，主要强化 #20 Agent Operations Agent，没有看到新的 Human/AI 工作对象。

### Restate — Reject Core

Durable execution 对生产 Agent 很关键，但属于 Runtime infrastructure，不是新的应用层工作方式。

## 今日最值得记住的一条产品创新养料

> **Agent 时代真正需要新增的，不只是 Agent Identity，而是 Delegation：知道“它是谁”远远不够，系统必须知道“它代表谁、被授权做什么、授权何时失效、谁为动作负责”。**

这也是今天相对于现有 30 个 Pattern 真正新增的研究增量。
