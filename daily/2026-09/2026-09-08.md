# AI 应用创新发现 · 2026-09-08

今天的主题是：**Agent 的能力不必静态配置，软件也可以开始动态组装和维护自己的能力。**

## Monid — ★★★★★
[产品深度卡片](../../products/monid.md)

真实问题：Agent 的工具通常由开发者提前接好；遇到新任务时，Agent 很难主动发现“我缺少一种能力”。

核心机制：**Capability-on-Demand**。Agent 在运行时发现能力缺口，搜索、比较、获取并调用新的能力。

为什么不是普通 MCP 市场：普通工具市场仍然由人挑选；这里把工具采购/选择本身纳入 Agent 的推理循环。

对本地 Agent 的启发：CLI、浏览器、MCP、脚本可以注册成带权限、成本和适用条件的 capability，由 Runtime 动态选择。

## Browzer — ★★★★☆
[产品深度卡片](../../products/browzer.md)

核心机制：**Source → Self-maintaining Artifact**。代码、业务规则或 Source of Truth 变化后，AI自动识别哪些文档、Demo、Changelog 等派生产物需要同步更新。

为什么重要：AI 不只是生成一次文档，而是长期维护 source 与 derived artifacts 之间的一致性。

## Nex — ★★★★☆
[产品深度卡片](../../products/nex.md)

核心机制：**Deterministic / Probabilistic Split**。稳定重复步骤用代码，不确定判断才调用模型。

可迁移原则：AI 并不是越多越好；真正好的 Agent 系统会主动减少运行时 LLM 参与。

## 主动淘汰
**Airuncode**：多 Agent、本地/云模型、自动测试等有工程价值，但核心体验用现有 Coding Agent + worktree + test runner + orchestration 即可重现，Composable Test 不通过。

## 今日产品创新养料
> AI-native 软件的一条重要方向，是从“AI 参与所有执行”转向“AI 动态生成、选择和维护可复用的软件能力”。
