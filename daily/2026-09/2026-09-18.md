# AI 应用创新日报 — 2026-09-18

## 结论

**今天没有发现达到核心创新标准的新产品。**

今天重点复核了 Docket Showroom、Naoma V2、Natural，以及若干新发布的垂直 Agent / Agent infrastructure 产品。最接近入选的是 Docket Showroom，但严格执行 Composable Test 后仍不足以进入核心产品库。

---

## 最接近入选：Docket Showroom（观察，不入选）

### 产品入口
- 官网：https://www.docket.io/
- Showroom：https://www.docket.io/features/showroom
- 官方介绍：https://www.docket.io/blog/ai-product-demos-showroom

### 已确认事实
Docket Showroom 把公司的真实 SaaS 产品界面加载到网站对话中。访客可以直接用自然语言提出“给我看看 X 怎么做”，Agent 在隔离 sandbox 中实时导航真实产品，并用语音/对话解释。它不是录屏、截图或预制 interactive tour。访客默认观看和聊天，也可以在允许时接管点击。每个 session 被限制在隔离边界内。

官方同时把这一能力延伸到 onboarding：用户真正遇到问题时再现场演示，而不是第一次登录时强塞固定 product tour。

### 真实问题
传统 B2B SaaS 的 demo 流程存在明显时序错误：用户产生具体问题的时刻，与真正看到产品回答问题的时刻相隔数小时甚至数天。固定 demo 又按销售脚本组织，而不是按当前用户的问题组织。

### 旧工作流
网站/文档 → 填表 → 排期 → 销售 Demo → 固定脚本 → 用户提问。

### 新工作流
用户产生问题 → 当场问 Agent → Agent 打开真实 sandbox → 根据问题实时走产品路径 → 用户继续追问/接管 → 必要时再进入销售或 CRM。

### 最值得看的产品变化
它把“Demo”从一个**预制内容 Artifact**变成一个**按问题即时生成的交互过程**。

过去 Demo 的基本对象是：
- 一段视频
- 一套 slides
- 一个 clone
- 一条固定 walkthrough

Showroom 的基本对象更接近：

`User Question + Live Product State → Generated Demonstration`

这确实改变了 demo 的时间、顺序和个性化方式。

### Composable Test：未通过强创新门槛
但核心体验今天已经可以由以下能力组合：

- Browser Agent / Playwright
- 一个 SaaS sandbox / demo account
- RAG / 产品知识库
- Voice / TTS
- 一个受限浏览器容器
- CRM / Calendar tool

1–2 天足以做出“用户问问题 → Agent 在真实产品里演示对应 workflow”的 80% 原型。

因此：**Docket 的产品化完成度可能很高，但这不等于一级产品机制创新。**

尤其 Naoma 已经在做高度相似的 live personalized product demo，并加入 returning visitor memory、qualification、CRM writeback。这说明它更像一个正在形成的新品类，而不是 Docket 独有的新机制。

### Human / AI / Software 分工
- Human buyer：从被动看固定 demo，变成提出当前问题并决定探索方向。
- AI：从“回答产品问题”升级为“把答案现场演示出来”。
- Deterministic Software：真实产品 sandbox、权限边界、隔离 session、CRM/Calendar 等继续负责可信执行和状态。

### 与历史模式比较
最接近：
- Pattern 01 Human Signal + Machine Context：用户问题成为方向信号。
- Pattern 02 Existing Surface → AI Action Layer：AI 直接进入真实产品表面。
- Pattern 13 Deterministic / Probabilistic Split：AI 决定演示路径，真实软件负责确定性行为。
- Pattern 29 Operational Model：如果未来 Docket 能持续学习产品操作模型，则可能进一步接近该模式。

**今天没有证据证明它新增了一个独立于上述模式的新一级机制，因此不新增 Pattern。**

### 对本地 Agent / B/G 的启发
值得抄的是“Question → Live Demonstration”，不是 Docket 的销售包装。

在专家工作台里，可以变成：专家问“这个企业为什么被判为周期任务未完成？”系统不是返回一段解释，而是现场打开对应任务、检查证据、状态节点，并沿真实业务界面展示判断依据。

这是一种重要的交互原则：**能展示真实状态和操作路径时，不要只生成文字解释。**

### 不值得抄
- AI avatar / voice 本身。
- 销售资格判断 + CRM 回写。
- 为了“AI Demo”重新复制产品 UI。
- 如果已有 Browser Runtime，不需要另造一套核心执行层。

### 最大未知
Docket 没有公开足够技术信息说明它如何可靠理解任意客户产品、如何处理 UI 变化、权限差异、复杂多步 workflow，以及演示路径是否依赖人工配置。若这些仍需大量 setup，则“live in one click”的宣传需要谨慎看待。

### 跟踪判断
**3/5，观察，不进入核心库。**

如果后续证明它能从真实产品持续自动建立可靠的可执行 Product Model，并在产品变化后自动修复 demo workflow，那么价值会从“Browser Agent demo”升级到 Pattern 29 的强实例。

## 其他候选

### Naoma V2 — 观察
与 Docket Showroom 高度同类：live browser demo + conversational agent + qualification + CRM + returning visitor memory。产品完成度值得看，但没有新增一级机制。

### Natural — 不作为今日新品入选
Natural 为 Agent 提供持久、可验证身份、revokable keys、granular permissions 和 transaction history，并构建 agent-native payments。方向重要，但与已有 Pattern 22 `Agent as First-class Identity` 高度重合，同时属于支付/身份基础设施而非今天新增的应用层机制。

### Acceldata xFactory — 淘汰
从 business intent 构建 governed AI apps / agents，连接 federated data 并运行在 Spark/Trino/Kafka 等基础设施上。当前公开信息更像企业 AI 应用开发/治理平台，未看到新的 Human/AI/Software 组织机制。

### Earnix Agent Hub / Zendesk Specialized AI Agents — 淘汰
都是垂直业务 Agent + permissions + traceability + human oversight。商业价值可能很高，但属于已有 Agent workflow / governance 模式的新行业实现。

- 主动淘汰/不入选：**Natural、Acceldata xFactory、Earnix Agent Hub、Zendesk Specialized AI Agents**

## 今日产品创新养料

> **AI 最有价值的回答不一定是生成一段更好的文字；当答案本来存在于可运行的软件中，AI 可以把“解释”升级成“现场证明”。**

但这条原则本身目前仍可以由 Browser Agent + sandbox + Context 快速拼出，所以今天把它保留为产品设计养料，而不是新增一级模式。
