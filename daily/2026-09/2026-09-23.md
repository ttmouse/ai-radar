# AI 应用层创新雷达 — 2026-09-23

## 结论

**今天没有发现达到核心创新标准的新产品。**

核心入选：0

重要旧产品更新：Meta Muse — Human Concierge  
重点观察：Ringer、Collibra Agent Contracts、Proofpoint Agentic Data & AI Security

## 今日最重要的变化：Meta Muse 开始测试 Human Concierge

Reuters 2026-09-22 报道，Meta 正在内部测试 Muse 的 “human concierge / human agent calls”：Muse 的电话任务可以交给受训人工，由人工实际拨打电话并完成任务。Meta 表示仍在测试，正式发布前会加入适当披露；部分员工担忧敏感信息可能被意外暴露给呼叫中心承包商。

### 为什么值得记录

表面看是 AI 不够强，找真人补洞。真正值得观察的是另一种 Agent Runtime：

User Intent → Agent-owned Task → Capability Router → {AI / Deterministic Software / Human} → Result → Agent-owned State

用户面对的是持续的 Agent / Task；底层执行者可以动态变化。Human 不再只是审批者，也可能成为 Agent 可调用的执行能力。

### 为什么不新增 Pattern

Composable Test 不通过。Agent + human ops queue + handoff + transcript + state machine 在 1–2 天内就能做出 80% 原型。它更像 Pattern 14（Agent Workspace + Governance Layer）与 Pattern 17（Judgment Queue）的扩展，而不是新的一级产品机制。

### 真正的边界

如果人工只是偷偷替 AI 完成任务，这是 Wizard of Oz，不是产品机制创新。真正成立必须把 disclosure、permission、context boundary、execution actor、audit 和 responsibility 产品化。

### 对本地 Agent / B/G 的启发

Human-in-the-loop 不应该只有“批准 / 驳回”。更完整的执行模型是：

- Deterministic Software：规则明确、可重复执行
- AI Agent：处理不确定性、理解、推理和开放式执行
- Human Operator：承担模型能力不足、高风险判断、现实世界核查

三者围绕同一个持久任务对象协作，任务不因为执行者切换而断裂。

应急场景中，AI 无法判断隐患证据时，可以把“补充核查”委派给专家作为原任务的子任务；专家完成后，证据和结论直接回到原任务状态，而不是进入另一个割裂的模块。

## 候选筛选

### Ringer — 观察，不入选

Ringer 把 AI 电话能力作为 MCP Tool 暴露给 Claude 等 Agent，并支持通话过程中暂停、向人询问信息，再无缝继续通话。这个“mid-call human-in-loop”交互很干净，但本质仍是 Voice Tool + MCP + HITL；1–2 天可以拼出核心体验，不通过 Composable Test。

### Collibra Agent Contracts — 观察，不入选

Collibra 2026-09-23 发布 Maestro、Live Map、Guardian Agents，并提出 Agent Contracts。方向值得看：企业开始把 Agent 行为约束、数据治理和运行时控制显式化。但目前更接近 Agent Governance / Control Plane，属于基础设施和既有治理模式强化，暂不足以形成新的应用层 Pattern。

### Proofpoint Agentic Data and AI Security — 观察，不入选

把 Agent intent 与数据访问结合，在运行时检测、调查和修复风险行为。对 Agent-first 企业架构重要，但属于安全基础设施，不进入应用层核心库。

### Positive MCP — 淘汰

把营销产品组合通过 MCP 暴露给 Agent，属于 Tool Exposure。MCP ≠ 产品机制创新。

### Fujitsu Aurora — 淘汰

Voice-first IT service desk + RAG + autonomous workflows + ITSM integration，商业价值明确，但仍是 Voice Agent + enterprise context + workflow automation 的垂直实现。

## 与历史 Patterns 的比较

今天没有新增模式。Meta Muse 的 Human Concierge 主要强化：

- Pattern 14 — Agent Workspace + Governance Layer
- Pattern 17 — AI Work Queue / Judgment Queue
- Pattern 22 — Agent as First-class Identity（如果未来 Agent 对外保持责任主体、内部动态调用人工）

真正值得继续验证的候选抽象是 **Human as Callable Capability / Fallback Runtime**。只有当多个产品都把人工变成可路由、可授权、可审计、可恢复的标准执行资源，并由持久 Task/Agent 承接结果时，才考虑升级为独立 Pattern。

## 今日产品创新养料

> Human-in-the-loop 不应该只理解成“AI 做完，人来审批”。更完整的 AI-native Runtime 可能把 Human 也变成一种可调用执行资源：任务属于 Work/Agent，执行者可以在 Software、AI、Human 之间动态切换，但 State、Permission、Evidence 和 Audit 必须连续。

这条判断的反面同样重要：**偷偷用人工补 AI 的能力缺口，不是创新，只是 Wizard of Oz。**
