## 1. 重点观察：Arcjet Agent Runtime Security（Observe；跟踪 4/5；Novelty 2/4）
来源：
- [Arcjet Platform（2026-11-03）](https://arcjet.com/learn/arcjet-platform)
- [AI agent threat detection（2026-11-06）](https://arcjet.com/learn/ai-agent-threat-detection)
- [Agent Runtime Security（2026-09-17）](https://arcjet.com/blog/introducing-agent-runtime-security-observe-enforce-audit)
- [Secure coding agents Docs](https://docs.arcjet.com/coding-agents/)

**真实问题**：Agent 通过 CLI、MCP、队列和后台任务执行时，传统 Web 防火墙看不到工具调用的真实意图、上下文和权限。仅在 Prompt 里写“不要执行危险操作”不能构成执行约束。

**旧工作流**：Agent 读外部材料→模型决定→调用工具→事后日志/人工追查；审批、权限和安全检测散落在 Agent 和工具里。

**新工作流（官方描述）**：从 Hooks/SDK/OTel 采集 Agent 活动→识别用户、会话、工具和参数→确定性策略引擎给出 allow/hold/block→在工具真正产生副作用前执行 Gate→保留审计证据。11/06 文档把风险明确分为读取内容、目标主机、会话行为链和入口调用者四个表面，分别使用不同检测器。

**机制与分工**：
- Human：设定允许的业务动作、权限和审批边界。
- AI：提出工具调用、解释异常、调查风险；不拥有最终授权权。
- Deterministic Software：根据可信身份、资源、参数和策略，在副作用发生前决定是否放行并写入审计记录。
- **事实**：Arcjet 官方提供 SDK、Hooks、策略和审计设计；11/03 说明使用 Rego 策略引擎并返回 allow/hold/block。**合理推断**：统一策略可能减少不同 Agent 的授权漂移。**未知**：跨 Agent 覆盖率、Hook 绕过、断网故障策略、误报率、生产延迟、独立安全审计。

**Composable Test**：现有 CLI hooks + OPA/Rego + policy-as-code + SQLite 审计 + MCP gateway 可在 1–2 天内复刻单一 Agent/单一动作的 80% 演示；安全产品工程成熟度很重要，但不自动意味着应用层新机制。已有 #14/#15/#16/#22 覆盖，**不晋升 Core，不新增 Pattern**。

**可迁移原理**：权限控制要贴近真实副作用发生点；检测器输出是信号，授权是独立的确定性决定。对于本地 Agent，可先给“删除文件、发送邮件、更新 GitHub、修改数据库”四类动作加拦截层，记录 actor、resource、args、policy_version、decision、effect_id。不要复制完整商业控制台和威胁模型。

**应急管理/B/G 启发**：AI 可以提出“整改通过”“发出检查文书”，但企业主体、专家身份、证据范围、文书版本和审批状态必须由业务系统核验；尤其不能只在 Agent 对话层阻止越权。

**反证与高估风险**：如果工具仍可绕过 Gate 被直接调用，所有审批都是 UI 幻象；如果策略失败默认放行，则可能产生高危漏洞。需要验证 deny 是否真正阻止副作用，hold 是否可以超时绕过，审计是否与真实结果一致。跟踪 4/5。

## 2. 第二观察：Glasshand（Maturation，Observe；跟踪 3/5）
来源：[Product Hunt Glasshand（2026-11-05 发布）](https://www.producthunt.com/products/glasshand/awards)；[官网](https://glasshand.com/)。
**事实（厂商声明）**：Agent 可租用独立真实 iPhone/Mac，在远端设备上执行操作；租赁结束清除数据并恢复出厂设置。
**新旧差异**：原来 Agent 在浏览器/模拟器或人自己的设备执行；现在通过租用真实设备完成移动端 App 操作和测试。对 iOS 原生功能、硬件权限和真实应用兼容性有工程价值。
**Composable Test**：租用设备 + 远程控制 + Agent 工具即可复刻有限体验；真实设备供应、隔离和擦除难以在两天内可靠建成，但主要是基础设施交付难度，而非新交互/业务对象。与 #14 Workspace/Governance、#09 Headless、#22 Identity 重叠。
**未知**：跨设备任务恢复、App 登录凭据隔离、数据擦除审计、真实应用成功率。可借鉴远程真实设备作为独立执行环境；不值得本地团队自建硬件机房。
