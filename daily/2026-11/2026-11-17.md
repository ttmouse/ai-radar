## 1. 重点观察：Nod 的任务承诺、Memory 与执行真值（Observe；跟踪 4/5；新颖度 1/4）
**真实问题**：持续运行的个人 Agent 会宣称“已保存任务”“已完成提醒”“稍后检查”，但对用户而言，这些是可核验的业务承诺，而非自然语言回答。

**旧工作流**：用户提出提醒/检查要求 → Agent 在对话中回应完成 → 用户相信其已登记和执行。失效时，用户通常只能在事后发现。

**理想新工作流（分析建议，非 Nod 已完整交付事实）**：用户委托目标 → 软件生成持久任务对象并验证调度登记 → Agent 执行 → 确定性系统核验任务记录、外部副作用和用户通知 → 给出可验证回执；失败则进入明确的重试/异常队列。

**新证据（已确认存在的公开 Issue，尚未独立复现）**：
- 2026-11-13 #881：任务声称已保存，但没有对应任务记录；https://github.com/n8n-io/nod/issues/881
- 2026-11-13 #883：手动 Run now 显示 Done，但没有预期网页回复；https://github.com/n8n-io/nod/issues/883
- 2026-11-14 #896：Observer 在定时与延期检查之间生成重叠任务；https://github.com/n8n-io/nod/issues/896
- 2026-11-16 #922：OpenRouter 路径的 Memory recall 被取消，报告涉及 1 秒共享预算及模型推理时间；https://github.com/n8n-io/nod/issues/922
来源索引：https://github.com/n8n-io/nod/issues

**已确认事实**：上述标题、日期、问题编号与报告内容存在；Nod 已开源并提供任务/Memory/审批能力。**合理推断**：对话成功、调度成功、任务执行成功、业务副作用成功、通知成功之间可能存在缺乏统一核验的边界。**未知**：Issue 是否在特定版本普遍复现、是否已被修复、实际故障率、完整 Runtime/队列/事务实现。**分析判断**：不能把一条 Issue 当作系统整体不可靠的统计证明，但它们足以提出可验证的产品验收用例。

**Human/AI/Deterministic Software 分工**：Human 负责目标、授权、异常处理；AI 负责理解委托、规划与动态决策；确定性软件必须负责任务登记、唯一执行 ID、幂等、实际状态核验、回执与异常记录。Memory 负责提供背景，不应替代任务系统的 Source of Truth。

**Composable Test：不通过强创新门槛**。PostgreSQL/SQLite + Cron/队列 + Agent Runtime + 审批日志 + 状态机 + 回执校验，在限定场景 1–2 天可以实现 80% 核心体验。可靠性改进重要，但不是新的 AI 原生交互原语。

**架构证据边界**：Runtime、Memory、定时任务、审批存在为公开产品事实；其内部事务边界、状态一致性机制、回执策略未在本次证据中得到完整验证；上述理想流程是建议，不应误记为 Nod 现有架构。

**与历史模式相比真正新增什么**：#06 Persistent State、#15 Proposed Action、#20 Agent Ops、#26 Agent-facing System of Record、#27 Context Belongs to Work 已覆盖原则；本次新增的是更具体的**可证伪验收用例**（任务已保存却无记录、完成却无结果、跨调度重复、Memory 超时），而非新的模式编号。

**可迁移原理**：Agent 的每一个涉及未来行动或外部副作用的陈述，都应可关联到一个真实、持久、可审计的状态对象；“完成”必须指向可验证结果，而非 Agent 的自述。

**本地 Agent 复刻建议**：做最小 Task Ledger（task_id、intent、schedule_id、run_id、expected_effect、actual_effect、receipt、error）；注入四类故障（调度登记失败、执行成功但通知失败、重复触发、Memory 超时）；断言不得虚报成功。无需复制 Nod 整套桌面虚拟机、连接器或完整个人助理。

**应急管理/B/G 迁移**：周期检查、整改提醒、专家复核、检查文书都要区分创建、登记、执行、外部生效、业务闭环。尤其不得将 AI 的“已下发”当作实际文书送达；应由业务系统提供回执。

**最大反证/高估风险**：这些属于通用分布式系统可靠性问题；如果现有工作流引擎即可解决，不能作为新的产品创新。只有出现新的委托/监督交互方式，并验证能显著降低人的监督负担，才重新考虑晋级。
