## 1. 主观察：Box Architect（Observe，跟踪 4/5，创新 2/4）
官方 2026-11-05：[Architect 产品文章](https://blog.box.com/box-unveils-architect-reimagine-content-workflows-frontier-ai)；[BoxWorks 公告](https://blog.box.com/boxworks-2026-box-brings-frontier-ai-business-workflows-enterprise-context-and-control)。

### 真实问题、旧与新流程
企业流程负责人知道结果（客户入驻、合同审核、保险理赔），却不一定能设计完整的表单、数据结构、审批、异常路由、应用界面和运行监控。
旧：人访谈/画 BPMN → 产品和工程配置表单、字段、审批、集成 → 上线后人工发现瓶颈再迭代。
新（官方规划）：人描述业务结果 → AI 结合 Box 内制度/文件提出步骤、分工、例外与假设 → 自动组装 Forms、Extract、Automate、Agents、Doc Gen、Sign、Apps → 人审查测试 → 部署 → 根据瓶颈提出改进建议。

### 机制与 Composable Test
最有价值的机制不是自然语言生成工作流，而是**目标、组织资料、工作流组件、运行反馈与改进提案的闭环**。但现有 LLM + n8n/Temporal + 文档检索 + Forms + MCP + 规则引擎，1–2 天可组合有限场景的 80% 演示；要成为强创新，必须证明持续运行反馈能可靠地修改有权限、有版本、有验收约束的业务对象。当前公告主要用 “will / could” 描述，未给出独立真实客户运行结果。因此不入 Core。
- Human：定义结果、验收、业务例外、风险审批。
- AI：提出流程结构、组件、优化建议；不应直接改变已批准的业务规则。
- Deterministic Software：文件权限、状态机、字段校验、审批授权、日志、真实运行指标。
- 已确认：官方明确列举预期集成组件、人员复核、权限治理与发布后优化方向。
- 合理推断：如果业务语义和流程运行状态打通，流程设计会从一次性项目变为持续优化对象。
- 未知：Architect 的实际开放范围、自动组装质量、异常处理正确率、部署/回滚和跨系统写操作安全性；不能将发布愿景视为 GA。
- 分析判断：#03/#05/#09/#13/#15/#26/#29 已覆盖，不新增模式。

### 迁移与最小复刻
本地 Agent 已有 CLI/浏览器/MCP/文件访问：可先实现 `OutcomeSpec → WorkflowProposal → Deterministic Gates → TestCases → ApprovedDeployment → Telemetry → ChangeProposal`。应急管理选“隐患整改复核”一个闭环，明确检查证据、规则、专家裁决和回滚；AI 只能提议流程修改。不要抄整套 Box 组件、模型路由或平台界面。反证：如果 AI 生成的流程仍需人重新梳理所有关键例外，则只减少了画图成本，未改变流程组织机制。

## 2. 第二观察：Perplexity Teammates（Observe，跟踪 3/5，创新 1–2/4）
来源：[The Verge，2026-11-06](https://www.theverge.com/ai-artificial-intelligence/1028302/perplexity-teammates-ai-agents-work)。报道指出可持续工作的角色型 Agent、多个任务线程、项目/Skills/Memory、Slack 协作和 Perplexity Computer 连接，Max 套餐门槛每月 $200。
- 旧：人向聊天助手分次提问；新：把持续任务委派给具角色的 Agent 并在不同线程追踪。
- 已确认：媒体报道上述产品主张；未知：独立权限身份、组织级审批、持久 Memory 的作用域与可靠性、任务交接的完整数据模型。
- Composable：现有 Agent Runtime + Slack + 定时任务 + SQLite + Skills 即可复刻主要演示。与 #03/#06/#21/#22/#27 重叠，不能因为“数百 AI 同事”的愿景新增模式。
- 可迁移：把“持续责任域”和“单次任务”分离；不要复制角色数量和聊天式看板。真正的价值需要证明跨任务接手成本降低、错误责任可追溯。

## 5. 结算与创新养料
**Core 0，Observe 2，Reject 2，Maturation 2，新 Pattern 0。**
> **AI 能生成工作流，不代表它理解了企业真正不可违反的规则。** Human 负责定义目标与例外；AI 负责提出可测试的流程；确定性软件负责状态、授权、验收、运行证据和可回滚的变更。真正的机制创新，要让流程从“生成一次”变成“受约束地持续演化”，并证明这种演化优于现有软件组合。
