**结论：今天没有发现达到核心创新标准的新产品。**

检索范围：Fresh 2026-11-17 至 11-20（24–72h）；Maturation 2026-11-06 至 11-13（7–14d），补查近期观察产品的后续 Issue/Release。仅英文来源。注意：搜索索引对最新 24 小时存在滞后，不能把“未发现”理解成全球不存在。

## 今日研究结果

- Core：0；Observe：2（Liminal、Nod 新证据）；Reject/去重：2（AgentConnect、Backdrop）；新正式 Pattern：0。
- 最值得保留的发现：**本地文件可以成为跨 Agent 的共享工作对象，但文件同步不等于多人协作的一致性、授权或真实完成。**

## 重点观察：Liminal — Agent 直接写文件，UI 实时呈现

来源：[Product Hunt 英文产品说明](https://www.producthunt.com/products/liminal-4)。

### 问题与工作流
旧工作流：个人 Agent 在本地生成 Markdown/HTML → 人手动发布/分享 → 其他成员复制上下文 → 再次让各自 Agent 理解。
新工作流（官方宣称）：Agent 直接写本地 Markdown/HTML → Liminal 即时渲染为可阅读/编辑 UI → CLI 同步到共享空间 → 团队与其他 Agent 通过文件获取工作上下文。

### Mechanism Delta
工作产物不必先进入某个 AI 专用聊天或数据库；**普通文件本身既是 Agent 可读写的状态载体，也是 Human 可编辑的界面来源**。值得注意的是“源文件与可交互阅读界面共享同一个工作对象”，而非又多一个聊天工具。

### Composable Test
**Composable but not proven structural.** 使用文件系统、Markdown/HTML Renderer、文件监控、Git/Syncthing、权限管理与 CLI Agent，可在 1–2 天复刻限定场景 80% 可见体验。技术可组合不自动否定创新，但当前没有证据证明其解决多人冲突、权限继承、变更来源、持久版本或真实团队默认工作流。因此 Observe，不进入 Core。

### Human / AI / Software 分工
- Human：定义目标、编辑与验收共享文件，决定发布范围。
- AI：写入和更新结构化工作产物，读取共享文件作为上下文。
- Deterministic Software：文件持久化、同步、渲染、访问控制、版本与冲突检测（后四项是应具备的设计责任，不代表 Liminal 已完整实现）。

### 事实 / 推断 / 未知
- **已确认的公开产品主张**：本地 Markdown/HTML 文件、浏览器即时渲染、CLI 同步、团队共享、Agent 直接文件访问。尚未独立实测。
- **合理推断**：减少 Agent 与人之间的格式转换和重复复制上下文。
- **未知**：并发写入冲突、权限隔离、同步失败恢复、文件可信度、离线合并、实际用户留存、内部 Runtime/Memory/Approval/Eval。
- **分析判断**：与 S.Space 相比，Liminal 更强调 filesystem-first，而非 Room-first；目前属于 #21、#27、#12 的实现变体，不是新 Pattern。

### 可迁移原理与复刻
对 AI 原生研发：让 PRD、决策、任务、代码产物通过统一文件及版本引用进入 Agent 工作流，减少聊天记录充当事实源。
对本地 Agent：优先复刻“Agent 写 Markdown → UI 渲染 → 人编辑 → 文件变更触发 Agent 重新读取”的闭环；测试并发写入、冲突、权限及历史回滚。已有 CLI/浏览器/MCP/文件访问，**不值得抄**另一个通用协作 SaaS 或单纯同步服务。
对应急管理/B/G：检查证据、隐患、整改结论不应只作为可任意覆盖的 Markdown；文件适合作为可审阅的工作视图，业务主键、状态机、审批和证据仍应由确定性 System of Record 管理。
最大反证：如果团队使用中仍依赖聊天解释文件变化，或文件同步无法保证授权/版本，那么它只是更顺滑的文件发布工具。
**跟踪价值 3/5；Mechanism Novelty 2/4；Evidence Maturity C。** 下一次晋级条件：公开可验证的多人协作流程、冲突解决与持久上下文效果。

## Maturation：Nod 的真实可靠性证据

来源：[Nod GitHub Issues](https://github.com/n8n-io/nod/issues)、[Nod Releases](https://github.com/n8n-io/nod/releases)。
- 11/18：#1096 报告定时任务消息标题在 emoji 中间截断时保存失败；#1065 报告 Windows 0.8.4 更新后旧 Skill 目录导致启动失败；#1017（11/17）报告 Composio 已连接但工具不可用。
- 11/16 v0.8.1 Release：明确处理连接服务 429/503 后延后 Gmail 检查，保留游标与已处理消息；跳过过期计划任务的后台状态轮询。
这些是 Issue 报告与官方修复说明，**不是独立故障率或全部问题已解决的证明**。与前期持续任务的结论一致：任务登记、可调用工具、实际执行、状态回执必须分别验证。
Nod 继续 Observe（跟踪价值 4/5），强化 #06/#15/#20/#26，无新模式。

## 主动淘汰/去重

- [AgentConnect](https://www.producthunt.com/products/agentconnect)：Slack/Telegram/Discord/GitHub 中调用跨运行时 Agent，角色/工具/Memory/权限组合。对 #04/#14/#22/#27 是成熟组合，未见新原语及独立生产验证，Reject Core。
- [Backdrop](https://www.producthunt.com/products/backdrop)：录屏教授工作流、共享上下文、Skill、审批和大量连接器。录屏学习有体验价值，但未证明自动化发现或组织责任发生新结构变化；与 #05/#08/#19 重叠，Reject Core。

## 今日产品创新养料

**Agent 共享同一个文件，不代表它们共享同一个可信事实。** 文件可以是低摩擦的上下文载体；版本、权限、冲突、业务状态和最终完成仍必须有独立的确定性机制。
