## 1. 重点观察：open-swe Goal mode（Observe，Tracking 4/5，Novelty 1–2/4）
来源：[open-swe GitHub Actions，2026-11-08](https://github.com/langchain-ai/open-swe/actions)（显示“feat(open-swe): goal tools anyone can call; stop Goal mode double rep…”及 CI 成功）。

**真实问题**：长时间运行的研发 Agent 需要把目标与具体一次对话/执行分离；Goal 模式如果重复报告或重复执行，会造成状态不一致。

**旧工作流**：人把目标拆成 issue 或指令，Agent 在单次任务里执行；跨会话续跑靠人工补充上下文。

**可能的新工作流（推断，非已证实的产品功能）**：目标作为持久对象→多个调用入口读取/操作目标→运行时负责避免重复报告→人按证据复核目标达成。

**可确认事实**：11/08 仓库出现 Goal mode 工具相关变更和通过的 CI；从 Actions 标题无法确认 API 语义、真实执行架构、权限模型、重复报告修复是否在生产部署，也无法证明目标已成为新的业务对象。

**Composable Test**：Goal 表 + SQLite + Cron/事件触发 + Agent Runtime + 幂等键 + GitHub issue/PR，1–2 天能组合限定场景主要体验；因此不能评为强产品机制创新。#03、#06、#15、#27 已覆盖其主要方向。

**Human / AI / Software**：Human 定义目标、验收和撤销；AI 提出计划与下一步动作；确定性软件负责目标版本、唯一执行 ID、去重、权限和已完成状态。这是建议架构，非 open-swe 已证实实现。

**本地可复刻**：只实现 Goal(id, owner, success_criteria, state, evidence, action_id) 和三态验收（confirmed/contradicted/inconclusive），测重复执行率、误判完成率、取消后动作发生率。不要为此复制完整 open-swe Runtime。**最大未知**：Goal 工具的权限/状态语义及真实任务恢复表现。继续跟踪 4/5。

## 2. 第二观察：Backdrop 的可审计 Agent 交接（Observe，Tracking 3/5，Novelty 1–2/4）
来源：[Backdrop Product Hunt](https://www.producthunt.com/products/backdrop)。创始人答疑称：Agent 将工作移交给另一 Agent 时，任务进入接收方队列，交接记录保留在任务对象中；跨 Agent 协作范围可由用户配置。另一条答疑确认可从屏幕录制中教授工作流。此处属于近期新增说明，**不是新产品发布**。

**核心值得研究的对象**：交接不应只是一段 Agent-to-Agent 消息，而应有 task_id、from/to、evidence、scope、acceptance、handoff_status 的可追溯状态。厂商目前只证实其声称有任务队列和交接记录；可靠性、权限检查及失败恢复未知。

**Composable Test**：Agent + Linear/Slack + Task Queue + Audit Log 即可复刻主要交接体验。#21、#22、#27 足以解释，不新增模式。对 B/G 产品，可用于专家→网格员→企业整改的责任移交，但不能把聊天消息当正式责任变更。跟踪 3/5。
