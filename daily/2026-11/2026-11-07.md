## 1. 主观察：Rerun（Observe；Tracking 4/5；Novelty 2/4）
来源：[Product Hunt 11/05 上线及创始人答疑](https://www.producthunt.com/products/rerun-2)、[GitHub 源码](https://github.com/rerun-build/rerun)。
**真实问题**：企业想让 Agent 持续追账、筛选线索、处理收件箱，但缺少易部署、可观察、可接管、能管理敏感操作的统一工作空间。
**旧工作流**：人工配置多个自动化工具、维护连接、定时触发、查看日志并处理异常。
**新工作流（厂商描述）**：自然语言向 Foreman 交代工作 → 规划 AI coworkers → 各自拥有 Memory、Skills、电脑和定时/触发执行 → 看板观察/接管 → 敏感动作先询问。
**可核实事实**：11/05 是第二次 Product Hunt 发布；第一次为 7/21；本次主要新增 AGPL-3.0 开源及自托管。GitHub README 说明 Next.js、Supabase、独立 workspace engine、MCP/API、Patchright、Docker 等组合架构；创始人确认一些能力仍 Cloud-only，且自托管和 Cloud 功能边界仍在补全。
**合理推断**：独立工作空间与电脑可降低跨任务上下文冲突；但没有可靠的成本、失败恢复、权限隔离测试。
**未知**：拒绝审批是否能抵御超时/重试覆盖；真实支付状态核验是否为确定性条件；独立部署的所有集成是否等价于 Cloud；长时间运行错误率。
**Composable Test**：Agent Runtime + Docker + Browser + SQLite + Cron + MCP + Approval Queue，1–2 天可以复刻限定场景 80% 核心体验。开源/自托管是可获取性变化，**不自动等于产品机制创新**。
**Human / AI / Deterministic Software**：人定义任务、风险边界与批准；AI 规划、操作与异常建议；确定性软件管理定时、权限、执行日志、幂等和真实业务状态（后四项是应有架构原则，不能全部当作已核实的 Rerun 实现）。
**迁移**：对本地 Agent 可复刻「业务状态检查→动作提案→审批→执行→再次核验」，例如催款前查真实回款；对 B/G 应急管理可用于隐患复核前先核验真实材料和主体状态。不要复制“AI 同事人数”、复杂聊天面板、全量集成目录。
**最大反证**：如果 Foreman 只是生成若干定时 Prompt，且人工仍需逐步核实结果，那么组织方式没有改变。跟踪 4/5，重点验证自托管能力边界和真实业务状态核验。

## 2. 第二观察：Snowflake CoCo / CoWork（Observe；Tracking 3/5；Novelty 1–2/4）
来源：[2026-11-03 企业公告转载](https://www.nasdaq.com/press-release/snowflake-coco-and-cowork-power-agentic-enterprise-grounded-governed-data-and-built)。
**已确认的发布主张**：Always-on bots 在后台工作，工作就绪或需要人的决定时才通知；可接 Slack/Excel/mobile，利用共享 Skills、Memory、Artifacts 持续积累。
**旧→新**：用户反复查询企业数据、手工导出分析→Agent 在受治理数据上主动运行、维护共享产物、按判断需求打断人。
**Composable**：Snowflake 数据层 + Cron + Agent + Slack + Dashboard 可构建类似工作流。#06/#17/#19/#21/#25 已覆盖。
**未知**：Agent 是否拥有可追责的独立身份；真实跨团队权限与审批；长期学习是否真正减少错误；不同业务数据的语义一致性。跟踪 3/5，不晋级。
