## 1. 重点研究：n8n Labs Nod（Observe；Tracking 5/5；Novelty 2/4）
**官方来源**：[n8n 发布博客（11/10）](https://blog.n8n.io/meet-nod/) · [GitHub 源码](https://github.com/n8n-io/nod) · [产品](https://nod.n8n.io/)。

**真实问题**：个人任务横跨邮件、日历、网页、供应商后台；通用聊天机器人不能持续执行，也缺少独立凭据保护、可审核的写操作和可见成本。

**旧工作流**：人反复切换软件和网页 → 手动登录、查询、填写 → 自己判断发送/支付/删除 → 事后核对结果。

**新工作流**：人交代一个结果 → Nod 在隔离的浏览器/工作区中执行、连接应用、保存个人偏好和任务状态 → 对原始请求未覆盖的敏感写操作进行单独信任检查和询问 → 记录操作、凭据使用与成本 → 人验收。

**关键机制**：把信任检查放在 Agent 之外的服务器执行路径，把密钥/支付信息保存在 Vault 而非模型上下文；个人 Memory 可追溯到用户消息，网页/邮件内容默认视为不可信数据；任务和调度带成本控制。特别重要的限制：**信任检查本身仍由模型判断**，不是完全确定性的安全证明。

**Composable Test**：用现成 Pi runtime/agent-browser、Docker、PostgreSQL、MCP、Vault、Hooks 与审批组件，在 1–2 天可搭出限定任务的 80% 体验；源码公开证明工程可组合。产品组合完成度有价值，但没有创造独立的新业务对象/交互原语；**不通过强创新门槛**。

**Human / AI / Software**：Human 定义任务、授权例外、验收；AI 理解意图、规划与执行、归纳 Memory；确定性软件负责容器隔离、凭据注入、状态持久化、成本阈值、动作日志，模型化 trust check 不能误称确定性策略引擎。

**事实**：官方公布 Apache-2.0、Mac/Windows 预览、单用户、自选模型、独立浏览器、Vault、日志、成本阈值；GitHub 说明 TypeScript/Node、Fastify、PostgreSQL/pg-boss、Pi、agent-browser、Composio/MCP/Electron。官方自测 226 个模拟任务各三轮，报告 98% 完成、678 次运行未出现不安全动作。**合理推断**：分离凭据与执行沙盒可减少直接泄密面。**未知**：真实网站成功率、越权误放行率、不同模型/提示注入下稳定性、供应商连接服务的信任边界、睡眠恢复与长期任务幂等性。厂商自测不是独立安全认证。

**最值得复刻**：三层授权（用户请求 → 独立动作判断 → 实际业务执行）；来源可追溯的个人 Memory；凭据永不进入模型；逐任务成本收据；网页数据不具有指令权。**不值得抄**：重新实现完整桌面虚拟机、20+ 模型 Provider、海量连接器；优先复用开源组件。

**对 AI 原生研发**：将“AI 认为获准”和“确定性执行许可”分开测；增加拒绝后重试、网页注入、已完成任务重入的回归用例。**对应急/B/G**：整改结论、文书下发、企业资料修改都必须由业务系统基于责任主体、角色、证据和审批状态作最终校验；不能把模型 trust check 当作法定授权。

**反证/高估风险**：研究预览、单用户、笔记本睡眠即停；安全模型会犯错，模型切换可能改变越权判断；有独立审批 UI 不等于执行点不可绕过。**跟踪 5/5**，重点等待权限绕过报告、真实长任务恢复和独立 Eval。

**与历史模式比较**：#03 Goal Work、#06 Persistent State、#14 Workspace Governance、#15 Proposed Action、#16 Context Supply Chain、#19 Memory、#22 Agent Identity 均已覆盖。真正新增的是一个**开源、可直接复用的组合实现与明确的安全失败边界**，不是新 Pattern。

## 2. 第二观察：LexisNexis Know Your Agent（Observe；Tracking 4/5；Novelty 2/4）
来源：[LexisNexis 官方公告，11/10](https://risk.lexisnexis.com/about-us/press-room/press-release/20261110-kya-gov)。

**真实问题**：政府在线服务以人为访问主体设计，自动化代理可能代替公民登录、领取福利、申请许可和支付，传统反机器人信号不能直接说明代理背后是谁、是否获授权。

**旧 → 新**：仅判断账号/设备/机器人风险 → 额外识别 AI Agent 活动作为独立风险信号，并结合身份、设备、行为、交易上下文决定进一步认证或限制。

**事实**：官方称能力已整合到 ThreatMetrix/BehavioSec，能检测部分 Agent 特征并送入现有风险决策。**推断**：政府可将“代理参与”作为风险评估维度。**未知**：真实识别率、误报、授权证明、代理主体绑定、不同浏览器/模型的可检测性；“检测到 Agent”不等于“知道委托人或授权范围”。

**Composable Test**：浏览器行为识别 + 风险规则 + 登录挑战能复刻部分体验，且仍属于 #22 Agent Identity、#26 Agent-facing System of Record、#13 Deterministic Split 的行业应用；不晋级。对 B/G 的核心启发是把 agent_presence、principal_identity、delegation_scope、transaction_authorization 分成四个字段，不要用一个“AI 标识”替代授权证明。
