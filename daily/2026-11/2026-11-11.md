## 1. 重点观察：Adobe Creative Cloud 原生文件 Agent（Observe；Tracking 4/5；Novelty 2/4）
来源：[Adobe 官方公告，2026-11-10](https://news.adobe.com/news/2026/11/adobe-transforms-creative-cloud-tools)；[The Verge 当日报道](https://www.theverge.com/tech/1030593/adobe-max-ai-agents-mcp-firefly-assistant-updates)。

**真实问题**：通用生成式 Agent 常输出扁平图片/视频或独立结果，专业设计师仍要把结果搬回原生软件、恢复图层和可编辑对象，难以接续原工作流。

**旧工作流**：人打开 Photoshop/Illustrator/Premiere → 手动选对象、调参数 → Agent 在外部生成内容 → 人工导入并重建可编辑结构。

**新工作流（发布/预览需区分）**：专业人员在原有 Creative Cloud 软件中委派多步骤操作；Agent 对原生工程的图层、片段、遮罩、颜色等可编辑对象执行操作；未来第三方 Agent 可通过本地 MCP 操作本机原生文件。

**机制**：把专业软件的语义对象和编辑能力暴露给 Agent，而非只生成最终图像。设计师保留审美/意图/验收；AI 规划并选择编辑动作；确定性软件维护图层、工程状态、版本和可逆操作。

**事实**：Adobe 11/10 宣布 Creative Agent 在 Premiere、Illustrator、InDesign、After Effects、Frame.io 等工具的覆盖和部分工作流；本地第三方 MCP 集成为 preview，The Verge 报道其私测预计 2027 年初开始。**推断**：原生语义编辑可能比截图点击更稳定。**未知**：工具调用粒度、复杂工程成功率、跨版本兼容、事务回滚、审批机制、Eval 和第三方 Agent 真正写入可靠性。

**Composable Test**：以 Photoshop scripting/UXP、Premiere API、MCP wrapper、现有 Agent，可以在 1–2 天构建针对几个明确编辑操作的核心演示；大量原生操作、兼容和回滚需要长期工程，但不是新的应用层交互原语。**不通过强创新门槛**。主要归属 #02/#09/#10/#13/#21/#27，暂无新 Pattern。

**可迁移原理**：Agent 最好操作具有语义、可验证状态和撤销能力的原生业务对象，而非仅通过屏幕像素模拟点击。对本地 Agent：优先为 Figma/设计文件建立“对象读取→提案→确定性修改→差异预览→确认”的受控链路；不值得复制 Adobe 全套创作模型。对应急管理：把“隐患、证据、检查文书、整改项”作为可操作语义对象，让 Agent 在原业务状态机中工作，而非生成一份脱离系统的 Word/PDF。

**反证/高估风险**：演示中可编辑不代表真实项目结构保持稳定；跨 Agent 编辑可能破坏图层/引用关系；缺少独立大样本测试。跟踪 4/5，等待 SDK 文档和真实工程回放。

## 2. 第二观察：OpenAI Business Agents / Business Hub（Observe；Tracking 4/5；Novelty 2/4）
来源：[OpenAI 官方公告，2026-11-10](https://openai.com/index/introducing-businesses-chatgpt/)；[The Verge 当日报道](https://www.theverge.com/ai-artificial-intelligence/1030552/openai-chatgpt-business-agents-hub)。

**真实问题**：用户在通用 AI 中发现商家后，仍需跳转网站，商家也难以维护 Agent 所使用的信息及官方身份。
**旧工作流**：用户搜索/询问 → AI 提供第三方商家信息 → 用户自行核对和访问商家网站。
**新工作流（Beta）**：企业在 Business Hub 认领/核验身份、维护资料；ChatGPT 在合适的商家展示场景提供标记明确、与个人对话分离的 Business Agent 交互。
**分工**：Human/企业维护政策和资料；AI 解释商品/服务并对话；平台维护商家身份和对话边界。**事实**：官方宣布面向美国部分电商/在线服务企业的 beta。**未知**：商家核验强度、Agent 的交易权限、实时价格库存连接、授权审计、用户转化及真实业务结果。
**Composable Test**：企业资料库+官方身份核验+Agent widget+CRM API 能快速做限定场景体验。相比 11/08 Tobira Site Agent 的“商家 Agent 面向消费者 Agent”，此处最大差异是嵌入 ChatGPT 入口与官方认领治理，而非新工作流模式。对应 #02/#09/#22/#26，**不晋级 Core，不新增 Pattern**。
**可迁移启发**：B/G 系统应明确“平台提供的企业资料”“企业自行声明”“已验证业务状态”三种来源；不能把已认领身份当作每一项业务事实的真实性保证。不要复刻流量入口，优先建设受治理的业务能力 API。
**反证**：若 Business Agent 仅回答静态 FAQ，没有实时业务动作和独立权限模型，则只是新的分发入口。跟踪 4/5。

## 3. Fresh 淘汰/去重
- **AIWG 2026.11.4 scoped saved approvals**：[GitHub release，11/10](https://github.com/jmagly/aiwg/releases)。支持对指定动作/文件/项目/环境的有期限、有限次数授权，并允许撤销；生产、破坏性、秘密操作继续审核。值得借鉴的“授权作为持久可审计对象”已由 #15/#22/#14 解释。通过 CLI hooks + policy store 可复刻限定体验；Reject Core，工程参考价值 4/5。
- **Gemini 4 Carbon + Antigravity swarm**：[The Verge，11/11](https://www.theverge.com/ai-artificial-intelligence/1030787/google-gemini-4-carbon-public-rollout)。模型能力与 swarm orchestration 是技术/编排更新；没有证据表明新的应用层业务对象或人机责任分工。Reject Core。

## 6. 今日结算
- 真正入选 **0**；Observe **2**；主动淘汰/去重 **2**；Maturation **2**；新 Pattern **0**。
- **产品创新养料**：**让 Agent 操作原生语义对象，比让 Agent 在屏幕上模拟人更值得关注；但能编辑对象不等于有权修改业务真值。** Human 定义意图与验收，AI 规划操作，确定性软件负责对象完整性、授权、差异和可恢复性。
